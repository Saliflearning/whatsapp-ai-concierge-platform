# Data Model

All identifiers are opaque strings generated by the application. Every mutable
or retrievable entity carries `business_id`; repository methods require it.

## Business

- `id` (primary key)
- `slug` (unique synthetic tenant key)
- `display_name`
- `default_locale`
- runtime webhook-secret and operator-token references
- `created_at`

## Conversation

- `id` (primary key)
- `business_id` (foreign key)
- `synthetic_customer_label`
- `locale`
- `status` (`open`, `handoff`, `resolved`)
- `created_at`, `updated_at`

## Message

- `id` (primary key)
- `business_id`, `conversation_id`
- `provider_event_id` (unique within business)
- `direction` (`inbound`, `outbound`)
- `body` (bounded synthetic text)
- `locale`
- `response_route` (`grounded`, `handoff`, `duplicate`)
- `knowledge_source_id` (nullable)
- `created_at`

## Knowledge Source

- `id` (primary key)
- `business_id`
- `label`
- `content`
- `keywords`
- `approved` (boolean)
- `updated_at`

## Handoff

- `id` (primary key)
- `business_id`, `conversation_id`, `message_id`
- `reason_code`
- `status` (`open`, `resolved`)
- `created_at`, `resolved_at`

## Audit Event

- `id` (primary key)
- `business_id`
- `conversation_id` (nullable)
- `event_type`
- `actor_type` (`system`, `operator`)
- `metadata_json` (bounded, non-secret fields only)
- `created_at`

## Invariants

1. All repository reads and writes include the authenticated `business_id`.
2. Provider event identifiers are idempotent per business.
3. Only approved, same-business knowledge may be attached to a message.
4. A handoff can transition from open to resolved once; repeated resolution is a no-op.
5. Audit events are append-only.
6. Seed content is visibly synthetic and resettable.
